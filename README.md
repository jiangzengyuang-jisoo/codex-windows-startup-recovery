# Codex Windows 启动恢复工具

[English](README.en.md)

用于缓解 Windows 版 Codex 正常启动后一直转圈：保留桌面窗口，只停止其所属的初始 `app-server`，让应用自行创建替换后台。

**这是非官方的临时恢复工具，不是对 Codex 启动缺陷的永久修复。** 作者已确认手动恢复有效，也已反馈原版快捷方式测试可用；不能保证所有电脑、版本或后续每次启动都有效。

## 已知环境与验证边界

- 已知受影响的正式版包：`OpenAI.Codex_26.924.2738.0_x64__2p2nqsd0c76g0`。
- 手动恢复后，实际工具执行 `Get-Location` 成功。沙箱设置 `errors=[]` 不能证明启动问题已解决。
- 本项目保留已测试快捷方式的三个核心源码文件；公开版另加了通用快捷方式创建脚本。
- 原有 28 项静态/模拟检查通过；测试不会激活应用或终止进程。跨电脑兼容性与所有竞态条件尚未验证。
- 进度窗口目前为中文；说明提供中英文。

## 方法一：创建桌面快捷方式

需要 Windows、已经安装并注册的正式版 Codex，以及现有 PowerShell 7。无需管理员运行。脚本不安装软件、不修改执行策略、不安装 Beta。

1. 下载仓库 ZIP 并**完整解压**到一个准备长期保留的文件夹；不要直接在 ZIP 内运行。
2. 检查源码。在独立的 PowerShell 7 窗口进入该文件夹，运行：

   ```powershell
   .\Install-Shortcut.ps1
   ```

   创建程序只生成桌面快捷方式，不启动或停止 Codex。已有同名快捷方式时会拒绝覆盖。也可以指定已有 PowerShell 7 的路径：

   ```powershell
   .\Install-Shortcut.ps1 -PowerShellPath 'C:\Program Files\PowerShell\7\pwsh.exe'
   ```

3. 等待所有 Codex 任务结束，正常退出应用，再使用桌面的 **Codex 启动并恢复**。
4. 即使主窗口先出现，也不要提前发送任务。等提示“后台恢复步骤已完成。不会再停止任何进程”，并确认界面可用后，再发送任务。

从互联网下载的脚本可能被 Windows 标记为不受信任。如果执行策略拦截，请先检查源码和下载来源；只有确认信任后，才在相应文件的“属性”中按需解除下载锁定。遵守组织策略，不使用 `Bypass`，不关闭安全功能。脚本不会自动解除锁定或修改策略。

### 入口的行为

- **已有桌面运行：只打开原窗口，不停止任何后台。** 若原窗口仍卡住，应在任务结束后正常退出，再用此入口新启动。
- 新启动走 `OpenAI.Codex_2p2nqsd0c76g0!App` 的正常 Windows 包激活入口，不直接执行安装目录的 EXE，不传调试参数。
- 核验 Windows 返回的 PID、启动前快照、创建时间、会话、路径与包族；只接受新桌面的唯一直接 `codex.exe app-server` 子进程，并比对其文件与安装包后台的 SHA-256。
- 等待桌面启动至少 35 秒、后台选定至少 3 秒，并确认页面进程存在；重新核验身份后，通过绑定的进程句柄**最多停止一次**。
- 等待替换后台并观察其身份稳定 5 秒。完成提示只证明后台重建流程结束，不证明页面已经加载完成。
- 连续双击使用互斥锁防止重复执行。身份不明、进程变化、后台不唯一、权限不足或超时就退出，不扩大匹配范围，不换目标重试。
- **它不检测是否正在转圈：通过该入口新启动时，每次都会尝试一次恢复。** 修复版本发布后应改用原入口。
- 不常驻、不添加开机项或计划任务、不修改应用包、不删除聊天或配置。原启动入口保留。

## 方法二：已经转圈时手动恢复

保持转圈窗口打开，确认没有任务运行，在**独立 PowerShell 窗口**执行 [Manual-Recovery.ps1](Manual-Recovery.ps1)，或复制里面的 `& { ... }` 整段到 PowerShell。

```powershell
.\Manual-Recovery.ps1
```

这会中断选中的后台。不要在正常工作的 Codex 对话中让工具执行它，也不要在有任务运行时使用。它是已经验证有效的简短快照式命令，保护措施少于新启动入口；不要改成终止所有 `codex.exe`。

## 文件与卸载

| 文件 | 用途 |
| --- | --- |
| `Start-Codex.ps1` | 有界的一次启动/恢复流程和提示窗口 |
| `Launcher.Core.ps1` | 纯进程筛选与身份检查 |
| `WindowsActivation.cs` | 正常包激活与绑定进程句柄 |
| `Install-Shortcut.ps1` | 在当前电脑生成快捷方式，不运行它 |
| `Manual-Recovery.ps1` | 用户主动执行的简短手动办法 |
| `tests/Test-Launcher.ps1` | 静态与虚构进程快照检查 |

日常运行后，`last-run.json` 仅记录本次状态、时间和相关进程号，可能包含错误路径；反馈前请检查并删除私人信息。它不上传任何数据，也不进入版本库。运行测试可用 `pwsh -NoProfile -File .\tests\Test-Launcher.ps1`。

**卸载：** 等启动提示结束，删除桌面快捷方式和解压文件夹即可。没有服务、任务或系统配置需要回滚。保留文件夹位置不变，否则已创建的快捷方式会失效。

## 35 秒版本的一次实际验证

2026-09-28，用户退出重开后，日志显示电脑操作组件在 22:33:37 就绪，后台于 22:34:03 执行一次恢复。配置自动更新为本次有效连接地址，实际列出窗口成功，浏览器控制也能打开 GitHub 页面。恢复前仍使用旧连接地址且无对应服务。这个结果支持保留 35 秒等待，但不能证明时序是唯一根因，也不保证每次启动都成功。
